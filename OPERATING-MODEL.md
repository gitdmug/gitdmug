# GITDM Operating Model

Six roles only. Every action produces a next state. Student service is the priority.

## Roles

| Role | Owns | Next hand-off |
|------|------|---------------|
| Admissions | Application → decision | Finance (accepted + invoice) |
| Finance | Payment verification | Academic (FULL access) |
| Academic | Teaching, classes, coursework | Exam Office (ready for formal exam) |
| Exam Office | Formal exams + marks | Registrar (FINAL grades) |
| Registrar | Permanent record, certificates | Alumni |
| Principal | Oversight + people assignment | — |

## Student journey

Visitor → apply → Admissions decides → Finance clears payment → Academic teaches → Exam Office examines → Registrar records → Alumni

## Academic rules

- Timetable is **auto-generated** from programme duration, fixed days/times, public holidays.
- A class becomes **actionable only 24 hours before start** (lecturer adds join link + materials; student sees join).
- Students track **full module/lesson progress** on My Programme (always visible once fee-cleared).
- Coursework assessments at **every third** of the programme.
- Formal exams: set (essay / multiple choice) → publish → student answers → mark → FINAL → Registrar.

## Page rules

- Bulk lists: table with search, filter, pagination (not endless scrolls).
- Open one row → dedicated detail page to work.
- Export / print where records matter (transcripts, invoices, results).
- No role switcher. One department, one portal.
